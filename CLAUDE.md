## 🔒 Security & Gotcha Prevention (Quick Reference)

| # | Gotcha | Prevention |
|---|--------|------------|
| 1 | Overconfidence in completion | Independent verification gate; machine evidence (`tsc`, `curl`, migration checksums). |
| 2 | Skipping initial code read | Mandatory `/primer` or reading `PROJECT_STATE.md`. |
| 3 | Branch / migration collisions | Claim numbers in `docs/MIGRATION_MASTER.md`; CI rejects duplicates. |
| 4 | Design docs without code | Tangible deliverable: route, test, screenshot. |
| 5 | Ignoring conventions | Use glossary (PRD Appendix C); lint disallowed terms (e.g., “KISS” in UI). |
| 6 | Forgetting dependencies | Publish API contracts first (`/contracts/`); contract tests. |
| 7 | Security as afterthought | Dedicated CI gate: `npm run security:preflight`. |
| 8 | Placeholders in production | Env validation script; zero tolerance for `your_` or `changeme`. |
| 9 | No end‑to‑end validation | Mandatory Playwright smoke tests before merge. |
| 10 | Dead code & logs | Pre‑commit hook blocks `console.log`; dead code audit in CI. |
| 11 | Contradictory status | Single source of truth: `PROJECT_STATE.md`. |
| 12 | Assuming environment ready | Run `npm run verify:env` (custom script) before deploy. |
| 13 | Not cleaning test artifacts | Transactional tests; dedicated test database; delete branches after merge. |
| 14 | Plan = Done fallacy | Never accept a plan as deliverable; require code, tests, evidence. |
| 15 | Reinventing utilities | “Reuse before build” check; auto‑lint for raw `fetch`. |
| 16 | No graceful degradation | Circuit breakers, exponential backoff, fallback messages. |

## 🔐 Auth Pattern (dual-auth)

Hotel Etuna uses **two** auth systems in parallel:
1. **Stack Auth** (primary) — JWT tokens, checked first in `getAuthenticatedUser` via `stackServerApp.getUser({ tokenStore: req })`
2. **NextAuth.js** (session fallback) — `getServerSession(authOptions)` used when Stack Auth is unconfigured or fails

Use `withApiAuth` / `requireTenantSessionUser` from `lib/utils/api-helpers.ts` for all protected routes — these handle the dual-auth cascade automatically.
